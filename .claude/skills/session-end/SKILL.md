# Конец работы

Оставить `TASK.md` в состоянии, из которого следующий заход начнётся без раскопок. Новых файлов
не создавать.

## Что сделать

1. Собрать факты одной командой:

   ```
   git status --short && git log --oneline -10 && git branch --show-current
   ```

2. **Перезаписать `TASK.md`** — именно перезаписать, а не дописать в конец. Файл отражает
   состояние на сейчас, а не историю того, как к нему пришли. Структура:

   ```markdown
   # TASK — состояние проекта

   **Этап:** <номер и одна строка, что он значит>

   ## В работе
   Что делается прямо сейчас и где оно лежит. Пусто — так и писать.

   ## Следующее
   Чеклист ближайших задач, в порядке выполнения. Не больше десяти пунктов:
   всё, что дальше, идёт в «Идеи».

   ## Открытые вопросы
   Решения, которые ждут Егора. Каждый — одной строкой, с вариантами.
   Вопрос, на который Claude может ответить сам, сюда не пишется: он решается.

   ## Техдолг
   Сознательно временные решения и чем их заменить.

   ## Идеи
   Незапланированное. Живёт здесь, пока не переедет в «Следующее».

   ## Сделано
   Только последние десять строк, по одной на законченную задачу, с датой.
   Всё старше — удалять: история есть в гите.
   ```

3. **Дописать новые грабли в `.claude/LESSONS.md`** — по строке на урок, с датой, в свой раздел.
   Только то, на чём реально споткнулись в этот раз и что повторится. Правило проекта, решение
   с обоснованием и частность одной задачи сюда не идут: им место в `CLAUDE.md`,
   `docs/decisions.md` и нигде соответственно.

4. **Незакоммиченное назвать явно** и спросить, коммитить ли.

5. **Доложить в чат четыре-пять строк:** что в `main`, что осталось хвостом, что ждёт решения
   Егора, с чего начинать дальше.

## Правила

- **Одна перезапись вместо роста.** Файл не должен пухнуть от сессии к сессии — в этом весь
  смысл. Раздел, который перестал быть правдой, удаляется, а не помечается как устаревший.
- **Честно про свои ошибки,** но коротко и только если из них следует правило: оно идёт в
  `LESSONS.md` одной строкой. Развёрнутых разборов не писать, их никто не перечитывает.
- Не дублировать гит: коммиты перечислять только там, где это объясняет состояние работы.
- `TASK.md` в гит не уходит. `.claude/LESSONS.md` уходит — дописанные грабли коммитятся.
