# Грабли

По строке на урок, с датой. Только то, на чём споткнулись здесь и что повторится.

Сюда **не** пишется: правила проекта (`CLAUDE.md`), решения с обоснованием (`docs/decisions.md`),
частности одной задачи (нигде), пересказ сделанного (`TASK.md`).

## Ядро нагрузки

- 2026-09-20 — Горутина, пишущая в канал, обязана иметь выход через `ctx.Done()` в том же
  `select`: иначе при остановке она виснет навсегда, а `wg.Wait()` не возвращается.
- 2026-09-20 — При выходе по ошибке отменять собственный производный контекст до ожидания
  горутин, иначе уже улетевшие отправки блокируются на записи в канал, который никто не читает.
- 2026-09-20 — Разводить ошибки конфигурации и рантайма: одна ошибка на «кривой потолок» и
  «упёрлись в потолок» делает диагностику невозможной.
- 2026-09-20 — `WorkerPool.Run` гасит прогон через `poolRun.fail` — он записывает первую фатальную
  ошибку и отменяет `sendCtx`. Любой новый «прогон дальше не идёт» вешать туда же, а не заводить
  вторую половинчатую тропу отмены.
- 2026-09-20 — Если отправитель не заполнил отметку времени, пул подставляет свою. Без этого в
  отчёт уезжают отрицательные длительности.
- 2026-09-20 — In-flight слот освобождать сразу после `Send`, до записи результата в канал:
  иначе медленный читатель результатов держит слот и прогон падает по мнимому потолку.
- 2026-09-20 — Подавляя фатальную ошибку отправителя, вызванную отменой контекста, не забыть
  подстраховку: если дальше никто не сообщит об отмене (например, канал запросов уже закрылся
  раньше, чем контекст отменили), `finish` должен сам вернуть `sendCtx.Err()`, иначе прогон
  молча отчитается об успехе.
- 2026-09-20 — Тест на «слот не держится дольше отправки» с нулевой задержкой у отправителя и
  буферизированным `in` — гонка планировщика Go, а не проверка бага: burst из горутин может
  упереться в потолок ещё до того, как рантайм успеет их запустить. Пейсинг через небольшой
  `time.Sleep` между отправками — законное исключение из правила «не спать вместо канала»,
  когда именно реальное время и есть предмет проверки.

- 2026-09-20 — `hdrhistogram-go`: `ValueAtQuantile(q)` — алиас `ValueAtPercentile` со шкалой
  0–100, а не квантиль. `ValueAtQuantile(0.99)` возвращает почти минимум выборки. Имя врёт,
  компилятор молчит. Пользоваться только `ValueAtPercentile`.
- 2026-09-20 — `hdrhistogram-go` не потокобезопасен ни в одном методе (`sync` в пакете не
  встречается вовсе): шардирование обязательно. `RecordValue` при выходе за диапазон возвращает
  ошибку и значение теряет — ошибку обязательно обрабатывать.

- 2026-09-20 — `hdrhistogram-go`: `Merge` в десять раз дороже `Export` (99 мкс против 9.7 на
  гистограмме 1мкс–1час). Для слияния складывать сырые счётчики снимка, а не звать `Merge`.
- 2026-09-20 — Запись в HDR под мьютексом при восьми горутинах в борьбе — 27 нс. Шардирование
  счётчиков на наших RPS не нужно: замерить, прежде чем усложнять.
- 2026-09-20 — `hdrhistogram-go`: значение ниже `lowestDiscernibleValue` не ошибка — попадает в
  бакет 0 с полной точностью. Ошибку `RecordValue` даёт только выход за верхнюю границу (и
  отрицательные значения, которые переполняют индекс). Не путать «низкое значение» с «вне
  диапазона».
- 2026-09-20 — `Bar.To` (`highestEquivalentValue`) из-за относительной точности бакета может
  заметно превышать «круглую» границу (100 мс бакет даёт `To ≈ 100.03 мс`, час — на секунды
  больше часа). Тесты, сравнивающие перцентиль с ожидаемой круглой цифрой, должны закладывать
  этот люфт, а не бить на равенство.
- 2026-09-20 — Перцентиль по рангу и `countBelow` в `pkg/metrics` считаются одним проходом
  `Distribution()` за `Snapshot()`, результат — кумулятивные бары с бинарным поиском на каждый
  вызов `Percentile`. Повторный проход `Distribution()` на каждый перцентиль был бы лишней
  тратой на ~23 тысячи бакетов при каждом p50/p90/p99 в одном отчёте.

- 2026-09-20 — Один оборванный запрос из ста НЕ делает p99 неопределённым: ранг p99 равен 99, а
  измеренных ниже порога ровно 99. Неопределённость начинается с двух. Тест, ожидавший обратного,
  был неверен, а не код.

- 2026-09-20 — Спарклайны масштабировать по диапазону значений, а не от нуля: ровные 848 RPS при

- 2026-09-20 — Вкладка, меняющая настройки стрелками, требует явного входа по `enter`: при

- 2026-09-20 — `bubbletea` без TTY зависает: в неинтерактивном режиме нужен построчный вывод.
- 2026-09-20 — Клавиши проверять живым прогоном. Тесты гоняют обработчик напрямую и четыре
  сломанные клавиши пропустили — все нашёл Егор руками.

- 2026-09-20 — `revive` требует `context.Context` первым параметром даже в тестовых хелперах.

## Инструменты и процесс

- 2026-09-20 — Шаблон в `.gitignore` без ведущего слеша совпадает и с каталогом: строка
  `grpc-loadgen` съела `cmd/grpc-loadgen/`, и точка входа месяц не попадала в репозиторий.
  Имена бинарей писать как `/grpc-loadgen`.
- 2026-09-20 — Перед созданием orphan-ветки проверять `git status`: незакоммиченные файлы
  удаляются вместе с остальным и не восстанавливаются.
- 2026-09-20 — Не предлагать fluent-интерфейсы и билдеры там, где источник данных YAML: структура
  плюс валидация проще и не прячет ошибки внутри цепочки вызовов.
- 2026-09-20 — Имя джобы CI, попавшее в обязательные проверки ruleset, не должно содержать версию
  Go: подъём матрицы молча ломает мердж всех PR. Держим сводную джобу `tests`.
- 2026-09-20 — Подагент пишет комментарии на языке спецификации: примеры API на русском в
  задании дали русские doc-комментарии в коде. Писать примеры сразу по-английски или повторять
  правило в каждой задаче.
- 2026-09-20 — Не править Go-файлы через python в heredoc: экранирование `
` и кавычек съедается
  дважды и ломает строковые литералы. Точечные правки делать инструментом редактирования, python
  оставить для markdown.
- 2026-09-20 — `print()` с кириллицей в python-скрипте падает на cp1252 и откатывает всю правку,
  если запись файла идёт после вывода. Выводить только латиницей.
- 2026-09-20 — Подагент стартует холодным и тратит бюджет на поиск по репозиторию. Давать точные
  пути, точный список случаев и прямой запрет искать: так расход падает вдвое.
- grpc-go не делает недоступную цель ошибкой сам: TRANSIENT_FAILURE → backoff → повтор, бесконечно. Ожидание Ready без выхода по TRANSIENT_FAILURE висит на опечатке в адресе.
- Время на Windows грубое: `time.Now()` дважды подряд может вернуть одно значение. Тест, выбирающий путь кода по разнице в наносекунды, на Windows и Linux проверяет разное.
- `-race` локально не собрать: нет gcc (cgo), Docker Desktop выключен. Мутации, которые ловит только детектор гонок, проверяются в CI.
- Мутацию незакоммиченного кода откатывать копией файла, а не `git checkout`: он откатывает и саму реализацию. Сначала коммит, потом мутации.
- Python-heredoc с `'''...'''` превращает `\n` в настоящий перевод строки внутри Go-литерала. Для вставки Go-кода со строками — Write или Edit, не python.
- Правки Go-кода со строковыми литералами — только Edit/Write. python-heredoc, perl и sed в Git Bash на Windows ломают `\n` или молча не находят шаблон; проверять результат grep'ом.
- Сессия съела лимит: большие вставки файлов в вывод (Read целиком, sed по сотне строк, file-changed notes) — главный расход. Читать узкими диапазонами, не печатать файлы после правок.
- 2026-09-21 — В GNU sed `\`` — якорь «начало буфера», а не экранированный обратный апостроф: `s/\`/`/g` вставил апостроф в начало каждой строки TASK.md. Заменять обратные апострофы только python с `chr(92)` или инструментом редактирования.
- 2026-09-21 — Тест, где ScheduledAt в будущем, молча принимал отрицательный порог оборванного: баг прятался, пока ревьюер не нашёл его чтением. Плановое время в тестах — только в прошлом, и это правило для любого теста с порогами.
- 2026-09-21 — «Всё зелёное» по локальному `go test` без `-race` — не зелёное: CI с `-race` в это время был красным от гонки за stderr. «Готово» по конкурентному коду — только зелёный CI с `-race` (`gh pr checks`), локальные прогоны — предварительно. Слепое пятно закрывается установкой gcc (w64devkit, MSYS2, WSL).
- 2026-09-21 — `test (go 1.27.1)` не дублирует `tests`: гонку поймал он, а второй прогон — нет. Детектор гонок вероятностный, два прогона — две попытки. Из обязательных не убирать.
