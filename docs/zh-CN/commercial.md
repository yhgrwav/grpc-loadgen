# 商业使用会是什么形态？

[← 返回文档](README.md)

> 本页描述的是**预期**模式。付费部分目前尚不存在，也没有时间表。
> 写在这里是为了它日后不会成为意外。

## 哪些会始终免费

内核与 CLI 以 Apache License 2.0 发布，并将保持开源。这是一个完整的工具，而非试用版：
单机运行、任意数量的方法与任意速率、CI 阈值、报告。商业使用不受限制——
公司可以把 CLI 接入自己的流水线，无需付费，也无需与任何人联系。

## 哪些将会收费

一个独立的 control plane，面向单机与单次运行已不够用的团队：

- **分布式运行**——多台机器同时施压、同步启动、直方图正确合并为一份报告；
- **运行历史**——结果留存、版本之间对比、长期跟踪性能劣化；
- **仪表盘**——实时查看进行中的压测，分析已完成的结果；
- **集成能力**——通知、导出到监控系统、基于角色的访问控制。

预期形态是按组织订阅并提供免费试用期，计费依据是 control plane 本身，
而不是请求数或机器数。对于内网封闭环境，正在考虑自托管方案。

## 为什么这样划分

凡是单机就能完成的能力都属于开源部分。值得付费的是需要基础设施的部分：
协调多个压测机、保存历史、为团队提供界面。

技术上它们是同一个引擎。control plane 与 CLI 一样，只是内核之外的又一层外壳；
而指标从一开始就被设计成可以让多台机器的结果正确相加。

## 这对贡献者意味着什么

这正是 pull request 需要作者签署 [CLA](../../CLA.md) 后才合入的原因。它是许可，而非权利转让：
贡献的著作权仍归作者，项目获得的是再许可该代码的权利。没有它，闭源部分在法律上不可能成立，
而且事后无法补救——那将需要征得每一位历史贡献者的同意。

如果你使用开源部分，对你而言没有任何变化：Apache 2.0 是不可撤销地授出的，
已发布的版本将继续适用该许可证。
